# Phase 6 协议：判决反馈双分支均衡 + NLTCP 格形解码

状态：**草案，待 Oliver 确认后冻结**。冻结时在 `protocol.json` 写入 UTC 时间与本文件 SHA-256；冻结前不运行任何正式训练或评分。机读版本见 [protocol.json](protocol.json)。

## 1. 研究问题与假设

前五阶段及三位组员的结果表明：在 Volterra 前端之后，给符号级均衡器增加非线性容量（tanh 储备池、二次特征、大随机特征）没有稳定收益。符号级仍未被利用的信息是 **已判决的过去符号** 与 **NLTCP 编码记忆**：编码满足 `q_t = floor(q_{t-1}/2) + m_t`，是 3 状态格形码，原解码器逐符号判决，没有使用这一约束。

本阶段把方法二的框架保留为"两分支特征拼接 + 共同 Ridge 读出"，只改变分支内容：

- **前馈分支**：115 符号接收窗口（与现有强线性基线相同）。
- **反馈分支**：第一遍均衡器给出的硬判决符号序列。

| 编号 | 假设 | 被推翻的条件 |
|---|---|---|
| H1（主） | 前馈 + 判决反馈 + Viterbi，比 115 窗口 Ridge + 原逐符号解码的 BER 下界更低 | 第 6 节验证门槛未通过，或测试阶段多数工况不改善 |
| H2（分离） | 在已使用 Viterbi 的前提下，判决反馈仍有独立贡献 | DF + Viterbi 相对 Ridge + Viterbi 的配对区间跨 0 |
| H3（RC 贡献） | 反馈分支用储备池记忆判决历史，优于直接把 K 个判决作为特征 | DF-RC 三个种子均值不优于同来源的最佳 DF-tap，或区间跨 0 |

H3 不成立并不否定 H1/H2，但届时不能把收益归给 RC。

## 2. 已有的探索性观察（必须披露）

2026-11-16 至 11-18，在 index509 验证集（已多轮使用）上做过只读探索，未训练正式模型、未接触任何测试段：

- Viterbi 对已保存验证预测的单路 BER 下界相对降低 11–13%（所有模型、所有通道）。
- 两遍判决反馈（前 8 个判决，训练段用样本内判决）+ Viterbi：RX1 0.02437 → 0.01698，RX2 0.02868 → 0.02096。
- 在判决反馈上再加二次项无改善；大随机 tanh 特征严重过拟合。

因此本协议的候选和门槛 **部分受到验证集的探索性观察影响**，验证门槛不能作为确认性证据；确认性证据只来自第 7 节的一次性测试评价。

## 4. 模型与候选

### 4.1 固定组件

- **第一遍均衡器**：每路 115 窗口 Ridge（λ=1e-5，即现有 `ridge_low`），输出逐分量就近判为 PAM6 电平 {±1, ±3, ±5}。
- **反馈特征**：过去 K 个判决的 I/Q（除以 5），超出分段起点的位置补 0；"past+future"再加未来 K 个判决（两遍处理，离线可行）。
- **共同读出**：`[u115, 反馈特征, 1]` → Ridge，λ=1e-5，预测理想 I/Q。
- **XY**：每路分别预测后固定 0.5/0.5 平均（沿用原规则），再解码。

### 4.2 训练段反馈来源

- **crossfit（交叉拟合）**：训练段分成 5 个连续块；每块的判决由在其余块（剔除该块两侧各 128 符号）上拟合的第一遍 Ridge 给出，使训练判决的错误率接近部署时的情况。
- **teacher（教师强制）**：训练段直接使用真实理想符号作为反馈。

验证/测试段的反馈 **一律** 来自在完整训练段上拟合的第一遍 Ridge 的判决，永不使用标签。

### 4.3 候选（共 19 个，不追加）

| 家族 | 候选 | 数量 |
|---|---|---:|
| DF-tap | K ∈ {2,4,8,16} × 来源 {crossfit, teacher} × 范围 {past, past+future} | 16 |
| DF-RC | 反馈分支为 40 节点储备池（输入为过去判决的 I/Q，因果递推），crossfit；线性分支（Identity，算子范数 0.6，leak 0.7）与 tanh 分支（谱半径 0.9，leak 0.7）各 1 个；种子 200/201/202 全部报告 | 2 |
| DF-XY | K=8，past，crossfit；反馈判决来自 XY 第一遍平均输出（两路共享判决，破坏两路独立性，单独报告） | 1 |

### 4.4 对照（不参与选择）

原参数符号 LMS、115 窗口 Ridge、`linear80_low`、`dual40_reg`（第三阶段冻结配置）。

### 4.5 解码器

- **逐符号**：原 NLTCP 规则；非法 4/5 保留，报告固定 2-bit 上下界。
- **Viterbi**：每个 I/Q 分量独立的 3 状态格形，状态 `s = floor(q/2)`，允许 `q_t = s + m (m=0..3)`；欧氏距离度量；初始状态未知（三个状态代价均为 0）；对整段（含保护区）运行，只在 mask 内计分；输出 `m_t = q_t - floor(q_{t-1}/2)`，构造上不产生非法值。无可调参数。

所有均衡器 × 两种解码器全部报告，形成 {无 DF, DF} × {逐符号, Viterbi} 的 2×2 分解。

## 5. 指标

| 解码器 | 报告内容 |
|---|---|
| 逐符号 | 固定 2-bit BER 下界/上界、非法判决率、历史 auto BER、PAM4 对错误率 |
| Viterbi | 2-bit BER（无非法值，唯一确定）、PAM4 对错误率 |
| 均衡器输出 | 复数 MSE（解码前） |
| 诊断 | 第一遍判决错误率；错误 run 长度分布（检查判决错误传播）；训练/推理墙钟时间 |

**主指标**：XY 的 Viterbi BER。**参照基线**：115 窗口 Ridge + 逐符号解码（上下界都报告；H1 用下界判定，即把非法 4/5 记为 0 个错 bit，对基线最有利），以及 115 窗口 Ridge + Viterbi。

不确定性：256/512 符号移动块配对 bootstrap，2000 次，seed 404；先解码，再按逐符号损失重采样，各方法使用相同的块位置。区间为探索性，不做多重比较校正。

## 6. 验证阶段：选择规则与门槛（仅 index509）

1. 19 个候选全部在验证段评价。DF-RC 取三个种子各自指标的平均值。
2. 选择规则：取 XY Viterbi BER 最低的候选；平局时依次比较 RX1 与 RX2 Viterbi BER 的均值、特征维数更小者、K 更小者。DF-XY 也参与选择，但若选中，报告中须标明"跨偏振共享判决"。
3. **继续进入测试阶段的门槛**（全部满足）：
   - (a) 选中候选的 XY Viterbi BER 相对 Ridge + Viterbi 降低 ≥ 10%；
   - (b) RX1、RX2 的 Viterbi BER 均低于各自的 Ridge + Viterbi；
   - (c) XY 的 BER 差值（选中候选 − Ridge + Viterbi）在 256 与 512 块长下的 95% 区间均 < 0。
4. 未通过：停止，写负面结果报告，**不评价测试段**，不追加候选。

## 7. 测试阶段（一次性）

1. 门槛通过后写 `frozen.json`：选中配置、所有代码文件 SHA-256、前端哈希、本协议哈希、UTC 时间。之后不得修改任何代码或配置。
2. 对第 3 节列出的 10 个工况：用各自训练段拟合第一遍 Ridge 与选中的 DF 读出，在测试段 [20000,51200) 评价一次。同时评价第 4.4 节全部对照与两种解码器。
3. **H1 成立的标准**：选中方案 + Viterbi 的 XY BER 低于 Ridge + 逐符号解码 BER **下界**的工况数 ≥ 8/10，且 10 个工况相对变化的中位数 ≤ −15%。
4. **H2 成立的标准**：选中方案 + Viterbi 低于 Ridge + Viterbi 的工况数 ≥ 8/10，且 10 个工况的配对差值（512 块长）中多数区间 < 0。
5. 所有工况、所有方法、所有指标全部报告，不剔除不利工况。382 绝对错误数很少，单独注明事件数。
6. 测试结果不得用于修改方法；如需改动，另立 Phase 7 协议，且只能用新载荷数据确认。

## 9. 结论边界（预先声明）

- 即使 H1/H2 成立，收益来自判决反馈与编码结构，不来自线性/非线性 RC 的非线性；只有 H3 成立时才能说储备池有贡献。
- 判决反馈依赖第一遍判决质量；在 BER 更高的工况可能因错误传播而缩水，这正是测试阶段要检验的内容。
- 两遍 past+future 方案需要缓存整段数据，属于离线处理，延迟高于原链路。
- 单一 Tx 载荷，不能外推到新消息；需要新载荷才能做泛化宣称。
