# Phase 6 报告：判决反馈双分支均衡 + NLTCP 格形解码

日期：2026-11-19（UTC）。协议：[PROTOCOL.md](PROTOCOL.md)（冻结哈希见 [protocol_freeze.json](protocol_freeze.json)）。偏离记录：[deviations.md](deviations.md)。

## 结论

**H1、H2 成立，H3 不成立。** 在 10 个预先列出的历史测试工况上，选中方案 `dftap_K16_crossfit_past_future` + Viterbi 的 XY BER **全部低于** 115 窗口 Ridge + 原逐符号解码的 BER 下界，中位相对变化 **−33.6%**；相对 Ridge + Viterbi 也全部更低，中位 **−25.0%**，9/10 个工况的 512 块配对区间完全小于 0。收益随 Vpp 增大（第一遍判决错误增多）而缩小：200–300 mV 约 −50%，1000 mV 只有 −6%。

收益来自 **判决反馈与 NLTCP 编码结构**，不来自储备池：用 40 节点线性或 tanh 储备池记忆判决历史，均未优于直接把 K 个判决作为特征（H3 不成立）。

## 1. 方法（与协议一致）

每个 RX 通道：

1. 第一遍：115 窗口 Ridge（即 `ridge_low`）→ 逐分量就近判为 PAM6 电平。
2. 第二遍：`[115 窗口接收符号, 前 K 个与后 K 个第一遍判决, 1]` → 共同 Ridge 读出（λ=1e-5）。训练段反馈来自 5 折交叉拟合的第一遍判决。
3. XY 固定 0.5/0.5 平均后，用 3 状态 Viterbi 解码（`q_t = floor(q_{t-1}/2)+m_t`，欧氏度量，无可调参数）。

这是方法二框架（两分支特征拼接 + 共同读出）下的"前馈分支 + 判决反馈分支"。

## 2. 验证阶段（index509，10001–20000 符号）

19 个候选中，选中 K=16、交叉拟合、过去+未来判决。XY 指标：

| 方法 | 逐符号下界 | 逐符号上界 | Viterbi |
|---|---:|---:|---:|
| 原参数 LMS | 0.02163 | 0.02260 | 0.02022 |
| 115 窗口 Ridge | 0.00903 | 0.00995 | 0.00788 |
| dual40_reg（第三阶段双分支） | 0.00985 | 0.01072 | 0.00875 |
| **选中 DF** | 0.00539 | 0.00564 | **0.00470** |

门槛：(a) 相对 Ridge + Viterbi 降低 40.4%（≥10%）✓；(b) RX1 0.01716 < 0.02137、RX2 0.01860 < 0.02489 ✓；(c) 256/512 块配对区间 [−0.00441, −0.00213] / [−0.00431, −0.00231] ✓。

候选规律：交叉拟合明显优于教师强制（例如 K8 past：0.00559 vs 0.01003），因为教师强制训练时看到的反馈没有错误，与使用时不一致；加入未来判决后 XY 进一步改善。验证阶段解析的标签 token 未超出前 20000 个。

**分解**（509 测试段 XY）：Ridge 逐符号下界 0.00797 → 只加 Viterbi 0.00724（−9%）→ 只加判决反馈（逐符号下界）0.00454（−43%）→ 两者都加 0.00397。主要贡献来自判决反馈。第三阶段的 dual40_reg 在 10 个工况上都与 Ridge 相当，与之前的结论一致。

**错误传播**：判决反馈使错误更成簇。例如 509 中长度 ≥3 的错误 run 占比由 3.9% 升到 12.0%，但 run 总数由 482 降到 234。第一遍判决错误率超过约 15% 时（900–1000 mV），收益明显缩小。

## 4. 结论边界

- 10 个工况共用同一 Tx 载荷与标签；测试段曾被其他方法评价过，但未用于本方法开发。这是 **方法开发未使用的历史测试段**，不是独立新载荷盲测，也不是零样本迁移（每个工况用自己的训练段拟合）。
- 协议中的候选和门槛部分受到此前验证集探索的影响（已披露）；确认性证据来自测试阶段。
- 过去+未来判决需要两遍处理整段数据，属于离线方案，延迟高于原链路。
- 收益不能归给储备池或非线性：H3 不成立；判决反馈之上加二次项在探索中也无益。
- 每个工况只有一次采集，区间为同一采集内的块重采样，未作多重比较校正。
