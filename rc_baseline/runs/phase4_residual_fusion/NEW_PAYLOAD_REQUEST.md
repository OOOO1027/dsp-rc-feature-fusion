# 向助教索取／核对的新载荷数据清单

目前**有不同Tx参考文件证据，但没有确认完整可用的独立NLTCP载荷测试包**。`data36QAM.txt`与RF0.105参考的SHA-256不同，前40000采样零延迟相关约−0.0068；Sheet1/2明确引用前者，而Sheet3/等高线图引用后者。波形不同也可能来自成形、载频或序列移位，不能仅凭哈希/相关断定原始消息独立。

请先核对旧`data36QAM.txt`是否采用另一随机PAM4消息；若是，请补齐与其一一对应的以下项目；若不是，请生成新的随机载荷采集：

1. 新payload_id、PAM4生成随机种子/生成脚本、两路完整原始PAM4整数及自然二进制/Gray映射说明；不能仅换index、幅度或文件名。
2. 编码后完整理想I/Q符号、NLTCP编码器初始状态与终止处理；每个符号和标签精确对应关系，首尾填充/保护序列说明。
3. 实际发送的Tx波形txt（及可选仪器wfm）、采样率、sps、RRC roll-off/span、载频、相位、归一化、帧结构及采样原点。
4. 同次采集的RX1/RX2完整原始波形、帧/符号ID，明确每个RX index对应哪个payload_id与Tx哈希。提供采集时间、bias/VPP、通道衰减、硬件设置。
5. 至少区分开发/校准载荷与最终封存载荷；如使用条件内训练，应事先提供训练校准段与测试段隔离约定。若要验证对新消息的直接泛化，应另测旧载荷训练权重在新载荷上的冻结推理，不能和新载荷内重训混称。
6. 新载荷与现有509/513/382消息不同的证据，及至少数次独立采集噪声实现；样本数按目标BER与允许不确定度提前约定，不能看到成绩才延长或截短。

`data49QAM`、`data36qamQAM`、`pre_SNRest_36QAM`等其它文件的具体编码/用途仍须核对；目前没有各自成套NLTCP标签。`Data/`的64APSK标签属于不同调制任务，不能替代新NLTCP消息的评价真值。

本轮止损后未对这些候选文件执行模型测试，也未把不同index当作新消息盲测。此文仅为本地待确认清单，未向助教发送消息。
