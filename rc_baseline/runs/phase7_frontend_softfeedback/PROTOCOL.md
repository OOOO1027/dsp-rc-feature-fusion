# Phase 7 协议：前端全量训练 × 软判决反馈 × 局部非线性分支

状态：**草案，待 Oliver 确认后冻结**。冻结时另写 `protocol_freeze.json`，记录本文件与 `protocol.json` 的 SHA-256 和 UTC 时间；冻结前不运行任何正式拟合或评分。

## 1. 背景与问题

Phase 6（判决反馈 + Viterbi）在 10 个历史测试段上全部优于强线性 Ridge，但收益随 Vpp 增大而消失（1000 mV 仅 −6%）。之后在验证段上的探索（2026-11-20）给出三条线索：

1. 现有 Volterra 前端只用训练段前 10000 个**采样**（2500 个符号）单遍训练；改用完整训练段 40000 个采样后，Ridge 的 BER 在 509/529/535 验证段分别降低约 20%/26%/15%，且可与判决反馈叠加。
2. 用后验均值软判决代替硬判决作为反馈，在 509 验证段上再降约 14%，529 约 2%，535 无变化。
3. 中心 ±1 个符号的二次 + 三次特征（局部低阶非线性），在高 Vpp 下降低 2–5%；tanh 储备池则没有收益。

Phase 6 协议第 7.6 条规定：根据测试结果改动方法后，必须另立协议，并用未参与的数据确认。本协议据此设计：**开发只用验证段，确认只用从未被任何方法评分过的采集**。

## 2. 假设

| 编号 | 假设 | 对照 |
|---|---|---|
| H1（前端） | 前端用 40000 采样训练，优于 10000 采样 | 两者都配 Ridge + Viterbi，其余相同 |
| H2（主） | Phase 7 选中系统优于 Phase 6 系统 | Phase 6 系统 = 前端 10000 + 硬反馈 K16 past+future + 无非线性分支 + Viterbi |
| H3（软反馈） | 后验均值软反馈优于硬反馈 | 前端与非线性分支相同的成对单元 |
| H4（局部非线性分支） | 加入局部二次 + 三次分支有增益 | 前端与反馈方式相同的成对单元 |

H4 回答课程原问题中"非线性分支是否有用"：这里的非线性分支是低维、局部、显式的多项式特征，不是随机储备池。

## 4. 候选（2×2×2 = 8 个，全部在开发集上评价）

| 因子 | 水平 |
|---|---|
| F：Volterra 前端训练采样数 | 10000（原设定）/ 40000（完整训练段） |
| B：反馈方式 | 硬判决 / 后验均值软判决 |
| N：局部非线性分支 | 无 / 中心 ±1 个符号 I/Q 的全部二次乘积 + 逐项三次（21 + 6 = 27 维） |

固定部分（来自 Phase 6 选中配置，不再调整）：

- 前端：`ChannelPipeline.fit`，只改 `frontend_train_samples`；对齐、尺度、CAP、步长、抽头不变。两个 F 水平都用同一代码对每个采集重新拟合。对 Phase 6 用过的采集，F=10000 的重拟合必须复现已保存前端的 `frozen_hash`，否则停止。
- 第一遍：115 窗口 Ridge（λ=1e-5），训练段 5 折交叉拟合。
- 反馈：K=16，过去 + 未来，交叉拟合来源。
- 软判决：每个 I/Q 分量 `E[电平 | x] = Σ_l l·exp(−(x−l)²/2σ²) / Σ_l exp(−(x−l)²/2σ²)`，电平 l ∈ {±1, ±3, ±5}，等先验；σ² 取训练段交叉拟合第一遍输出相对真值的残差方差（mask 内、两分量合并）。
- 共同读出：`[u115, 反馈特征, (非线性分支), 1]` → Ridge，λ=1e-5。
- XY 固定 0.5/0.5；解码：Phase 6 的 3 状态 Viterbi。

参照（报告，不参与选择）：原参数 LMS；Ridge F=10000 + 逐符号（上下界）；Ridge F=10000/40000 + Viterbi；选中系统的因果版本（K=8，只用过去判决），供在线可行性参考。

## 5. 开发阶段：选择与门槛

1. 8 个候选在 10 个开发采集的验证段上全部评价。主指标：XY Viterbi BER。
2. 对每个候选 c、每个采集 i，计算 `r_ci = log(BER_ci / BER_Phase6,i)`。选择 **10 个采集上 r_ci 中位数最小** 的候选；平局时选开启因子更少者，再平局按 F < B < N 的顺序偏好不开启。
3. **进入确认阶段的门槛**（全部满足）：
   - (a) 选中候选相对 Phase 6 系统的中位相对变化 ≤ −5%；
   - (b) 在 ≥ 7/10 个开发采集上优于 Phase 6 系统；
   - (c) 在 7 个从未使用过验证段的开发采集上，中位相对变化仍 < 0（防止只靠反复使用的 509/529/535 过关）。
4. 未通过：停止，写负面报告，不读取确认集的任何数据。

## 6. 确认阶段（一次性）

门槛通过后写 `frozen.json`（选中配置、代码哈希、开发结果哈希），然后对 27 个确认采集：用各自训练段拟合两个 F 水平的前端和全部 8 个候选及参照，在测试段评价一次。8 个单元全部评价，是为了按预先声明的对照估计各因子的作用；**选择不会再变**。

计数规则：Phase 6 系统在某采集测试段的 XY Viterbi 错 bit 数 < 30 时，该采集照常报告，但不计入胜负比例的分母（判定只依赖基线，不依赖候选）。

异常处理（事先规定，不做临时调整）：

- **前端发散**：某采集某 F 水平的 Volterra 训练发散（`FloatingPointError` 或非有限权重）时，不改步长、不重试；该采集上使用这个 F 水平的所有候选计为"劣于对照"，并单独列出。
- **对齐异常**：某采集的训练段符号相关峰不在 lag 0（沿用 Phase 3 的检查，只用训练数据）时，该采集从所有比较中剔除并报告原因；剔除决定在评分前写入日志。

| 假设 | 成立标准 |
|---|---|
| H2（主） | 选中系统在 ≥ 80% 的有效采集上优于 Phase 6 系统，中位相对变化 ≤ −10%，且双侧符号检验 p < 0.01 |
| H1 | Ridge + Viterbi 的 F=40000 在 ≥ 80% 有效采集上优于 F=10000，中位 ≤ −5% |
| H3 | 4 对"软 vs 硬"成对单元合并后，按采集取中位相对变化 < 0，且每对单独的符号检验 p < 0.05 的对数 ≥ 3/4 |
| H4 | 4 对"有 vs 无非线性分支"成对单元，判定方式同 H3 |

另外报告：每个采集选中系统相对 Phase 6 系统的 512 符号块配对 bootstrap 区间（2000 次，seed 404）；按偏置电流 × Vpp 的结果网格；第一遍判决错误率与错误 run 长度。
