# 开发阶段异常：382 的 F=40000 前端发散后恢复为有限值

记录时间：2026-11-20。状态：**确认阶段暂停，未运行 `freeze`，未打开任何确认采集的文件。**

## 现象

开发阶段门槛形式上通过（选中 `F40k_posterior_mean_poly`，中位 −39.4%，9/10 胜，新鲜验证段中位 −52.8%）。唯一的失败是 382（50 mA / 200 mV）：

| 方法（382 验证段 XY Viterbi BER） | 值 |
|---|---:|
| Phase 6 系统（F=10000） | 0.00010 |
| 选中系统（F=40000） | 0.06432 |
| Ridge + Viterbi，F=10000 / F=40000 | 0.00013 / 0.06958 |

四个 F=40000 单元都失败，F=10000 单元都正常；问题出在前端，与反馈方式和非线性分支无关。逐通道看，RX1 从 0.0044 恶化到 0.22，RX2 正常。

## 原因（只用开发采集的训练段诊断）

RX1 的 Volterra LMS 训练误差按 1/8 段：

| 采集 / F | 各段训练误差 MSE |
|---|---|
| 382 / 10000 | 0.195 0.076 0.070 0.054 0.063 0.042 0.046 0.046 |
| **382 / 40000** | 0.099 0.049 0.049 **659 3.4e6 3.8e5 6.4e4 67** |
| 509 / 40000 | 0.088 0.061 0.056 0.056 0.063 0.053 0.054 0.055 |
| 535 / 40000 | 0.176 0.136 0.130 0.122 0.117 0.116 0.124 0.108 |

单遍 LMS 在 382 的训练段中途发散，之后部分回落，最终权重有限（|W| 175.7，F=10000 时为 2.8），因此协议第 6 节的发散规则（`FloatingPointError` 或非有限权重）没有触发。固定步长来自 509 的来源参数，在更高偏置电流的采集上可能不稳定。

## 对协议的影响

- 门槛判定按中位数与胜场计数，形式上通过；但该失败模式在协议设计时未被预见，而确认集（40/60/70 mA）与 382 的条件接近，复现概率不低。
- 按原协议继续确认，结果仍然有效（发散采集会如实计为失败），但会用掉 27 个从未评分过的采集。
- 若修改前端（例如加入只用训练误差的稳定性判据），属于方法改动，需要另立协议重新开发；确认集在此之前保持未触碰。
